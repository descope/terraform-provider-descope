# Adding a Resource

How to add a new standalone resource. For the model itself (attributes, struct, `Values()` and `SetValues()`), read
`internal/models/CLAUDE.md` first.

## The endpoint decides the constructor

Pick the constructor by the shape of the backend API, not by what the feature is:

- **Entity with a server-assigned id** on one route (`POST` create, `GET ?id=`, `PUT` update, `DELETE ?id=`): use
  `newResource` with operations written longhand in the resource's file. `newConnectorResource` in `operations.go`
  is the reference: Create reads the new id from the returned entity, Update puts the id in the body, and reads and
  deletes pass it as a query parameter.
- **Entity with a user-chosen id** (flows, widgets, attributes, OAuth providers): Create returns the id from the
  request data rather than the response, as in `flow.go` and `attributes.go`.
- **Entity scoped under a parent** (an application, an auth method): set `ScopedRead` and `ScopedDelete` instead of
  `Read` and `Delete`, as `NewAppPermissionResource` in `apps.go` does. The model needs an `app_id` or `method`
  attribute, must implement `GetAppID()` or `GetMethod()` returning it, and must emit it in `Values()`, since Create
  and Update send the scope in the body. Only these two scopes are supported: a new one needs changes to
  `baseResource`.
- **Singleton settings** on one `GET`/`POST` settings route: use `newSettingsResource` with the path. It always
  exists, its id is the project id, and destroying it only removes it from state.
- **Singleton on any other endpoint**: use `newSingletonResource` with Create left nil, as in `styles.go`.
- **Connectors** are generated by terragen from the content repo templates and registered in `connectors.go`. A new
  connector type needs `make terragen flags='--add-connectors'`, since terragen otherwise skips templates that have
  no connector file yet.
- Never use `newInfraResource` for anything new: the `/v1/mgmt/infra` endpoint is frozen.

Operations are plain closures over `infra.Client` in the resource's own file, so each endpoint's quirks are visible in
one place. Share them only between resources on the same endpoint, as `templateOps` and `attributeOps` do, and never
build a generic helper across endpoints. When the endpoint doesn't match the ideal shape (an envelope around the
entity, an id in the path, a delete through a `POST` body, a create that returns no body), the adapter goes in those
closures, as in `lists.go` and `authorization.go`, and the fix belongs in the backend.

## Steps

1. **Model.** Create `internal/models/<package>/` with the schema and model. Resource models implement
   `helpers.ResourceModel`: `id` is `stringattr.Identifier()` when the server assigns it, `project_id` is
   `stringattr.Required(stringplanmodifier.RequiresReplace())`, and `GetID`, `SetID` and `GetProjectID` return them.
   Declare the attributes as a single `var <Name>Attributes = map[string]schema.Attribute{...}` literal: terragen
   finds models only in that form, and silently generates no docs otherwise. The schema's `MarkdownDescription` is
   the resource's description in the registry docs.
2. **Replacement.** Every `RequiresReplace` other than on `project_id` must be listed in `replaceModifierAllowlist` in
   `internal/provider/provider_test.go`, which only accepts identity attributes of unprotected resources.
3. **Resource.** Add the constructor to a file here, named after the resource.
4. **Registration.** Add the constructor to the resources list in `internal/provider/provider.go`.
5. **Deletion protection.** Only for entities whose deletion loses something that can't be recreated from the
   configuration, such as applications with issued credentials. Add a `deletion_protection` attribute following
   `inboundapp`, and implement `helpers.DeletionProtectionDefaulter` returning true to protect by default. The
   attribute is never sent in `Values()` or read in `SetValues()`.
6. **Documentation.** Run `make terragen`, which writes the placeholders in `docs/raw/<package>/` and exits with an
   error by design. Replace every `//` placeholder with a description, then run `make terragen` and `make docs`.
7. **Acceptance test.** Add a helper for the resource in `tools/testacc/resource.go`, then a test in the model's
   package using `testacc.RunWithDestroyCheck`, or `testacc.Run` for singletons and method-scoped resources. Pack as
   many attributes into each step as possible, since every step is a full plan and apply, and include an import step
   that uses `testacc.GenerateImportStateID`.
8. **Sweeper.** If leaked test entities would pile up in the shared test project, add a target to `sweepTargets` in
   `tools/testacc/sweep_test.go`. It matches entities by a `testacc-` prefix on their `name`.
9. **tfexport.** Read `tools/tfexport/CLAUDE.md`. Singletons are exported automatically. An entity is exported only
   once discovery lists it, either from the project snapshot in `discover/index.go` or through a load-all endpoint in
   `discover/discover.go`, and `TestGenerativeCoverage` fails with a discovery gap until then. That test also applies
   a generated configuration of every resource, so attributes with restricted or coupled values need entries in
   `attributeValueOverrides` or `nestedValueOverrides` in `tools/tfexport/generative_test.go`.

## Import ids

`ImportState` parses the id by the resource's shape, and tfexport's `internal/export/export.go` derives it the same
way, so a new shape changes both:

- Singleton: `<project_id>`
- Entity: `<project_id>/<id>`
- Entity scoped by `method` or `app_id`: `<project_id>/<scope>/<id>`
- Resource without a `project_id` attribute, such as company-level resources and `descope_project` itself: `<id>`
